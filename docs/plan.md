# Migration plan: SvelteKit 2 → SvelteKit 3

## Approach

Instead of migrating this project in place, we scaffold a fresh SvelteKit 3 project next to it,
port the site code into it, and then replace the contents of this repository with the new project.

```
sv create  →  ../cloudflare-site-new     (fresh SK3 scaffold, incl. ai-tools)
port       →  site code moved into ../cloudflare-site-new
replace    →  ../cloudflare-site-new replaces this repo's contents on branch migrate/sk-3
```

`../cloudflare-site-new` is a local git repository (initial commit = untouched scaffold). Each step
below is committed there separately, so every change can be reviewed against the scaffold.

Git history, CI, Cloudflare secrets and Dependabot stay in this repository. The PR diff shows the
whole migration at once.

## Target versions

- `@sveltejs/kit` 3.x, `@sveltejs/adapter-static` 4.x, `sv` 1.x
- Node ≥ 22.17, TypeScript 6, Vite 8, Svelte ≥ 5.57.1, `@sveltejs/vite-plugin-svelte` 7

## SvelteKit 3 changes that affect this project

| Area           | SvelteKit 2 (current)                    | SvelteKit 3                                                       |
| -------------- | ---------------------------------------- | ----------------------------------------------------------------- |
| lib alias      | `$lib/...`                               | `#lib/...` via `package.json` `imports`; file extensions required |
| Hook types     | `Handle`, `Reroute` from `@sveltejs/kit` | from `@sveltejs/kit/hooks`                                        |
| Paraglide hook | `event.request = request`                | `resolve({ ...event, request }, ...)`                             |
| Path type      | `Pathname` from `$app/types`             | `Path`                                                            |
| tsconfig       | `extends ./.svelte-kit/tsconfig.json`    | `extends "$app/tsconfig"` + own `include` / `types`               |
| Adapter        | `adapter-static@3`                       | `adapter-static@4`                                                |

`resolve(localizeHref('/...') as Path)` keeps working: a string starting with `/` is treated as a
route ID without params and resolves to the same pathname.

Not relevant for this project: `$app/stores`, `goto` options, cookies, CSRF, remote functions,
`params`, service workers.

## Decisions

- Repository contents are replaced entirely by the new project. Only `.git` is kept as is.
- Package name: `cloudflare-site`.
- `ai-tools` is enabled during scaffolding; whatever it generates is what we use.
- Changesets are removed (`@changesets/cli`, `changeset:*` scripts). They are no longer used.
- `deploy-site/` (legacy static HTML site) is not carried over.
- All assets in `src/lib/assets/` are carried over, including currently unused images.
- The Playwright demo is kept (`playwright="demo:yes"`): its e2e test is the only smoke check that
  the site starts and a link works, in CI and against the Cloudflare preview. The vitest examples
  generated by the scaffold are kept too. We take whatever the scaffold generates and do not write
  new tests.
- The old paraglide demo route (`/demo/paraglide`) is not carried over.
- The scaffold's floating `DemoLinks` widget is removed (it would be visible on the live site).
  `/demo/playwright` stays reachable for the e2e test and is added to `prerender.entries`, since
  nothing links to it anymore and `adapter-static` only prerenders crawled pages.

## Steps

### 1. Scaffold

- [x] Create the new project in `../cloudflare-site-new`, `git init`, initial commit:

  ```sh
  npx sv@1.1.1 create --template demo --types ts \
    --add prettier eslint vitest="usages:unit,component" playwright="demo:yes" \
    tailwindcss="plugins:typography,forms" enhanced-img sveltekit-adapter="adapter:static" \
    paraglide="languageTags:en, de+demo:no" \
    ai-tools="ide:claude-code,vscode,other+delivery:plugin+tools:mcp,svelte-code-writer,svelte-core-bestpractices,svelte-file-editor+mcpSetup:remote" \
    --install npm cloudflare-site-new
  ```

- [ ] Set `"name": "cloudflare-site"` in `package.json`.
- [ ] Update all dependencies to latest (`sv` pins older versions, e.g. vitest 4, `@types/node` 24).
- [ ] Add `wrangler` as a dev dependency.
- [ ] Verify `npm run dev` starts.

### 1b. Remove the scaffold demo app

The `demo` template ships a sample app that is not part of the site:

- [ ] Routes: `sverdle/`, `about/`, `Counter.svelte`, `Header.svelte`, `+page.ts`; replace
      `+page.svelte` and `+layout.svelte` with empty placeholders.
- [ ] `src/routes/demo/DemoLinks.svelte` (keep `demo/playwright/` and its e2e test).
- [ ] `src/lib/images/` (Svelte logo, GitHub icon, welcome image).
- [ ] `layout.css`: drop the demo styles, keep the tailwind imports and plugins.
- [ ] Dependencies: `@fontsource/fira-mono`, `@neoconfetti/svelte`.
- [ ] `static/favicon.svg` and its `<link rel="icon">` in `src/app.html` (favicons come from the
      layout).
- [ ] Add `prerender: { entries: ['*', '/demo/playwright'] }` to the `sveltekit()` config.

### 2. Configuration

- [ ] `vite.config.ts`: add paraglide `strategy: ['url', 'cookie', 'baseLocale']`.
- [ ] `tsconfig.json`: carry over custom options (`lib`, `target`, `rewriteRelativeImportExtensions`,

- [ ] `wrangler.jsonc` (assets from `./build`, `html_handling: drop-trailing-slash`).
- [ ] `.npmrc` (`engine-strict=true`).
- [ ] `.gitignore`: carry over project-specific entries (Claude local files,

### 3. i18n

- [ ] `messages/en.json`, `messages/de.json` (drop the unused `hello_world` demo message).
- [ ] `src/app.html` (matches the scaffold once the favicon link is removed in step 1b).

### 4. Assets

### 5. Styles

### 6. Components and layout

### 9. Repository-specific files

Re-add onto the new project what the scaffold does not generate:

- [ ] `.github/workflows/*` (CI, release, auto-merge, codeql, contribution-*), `.github/dependabot.yml`.
- [ ] `.githooks/pre-push`.
- [ ] `scripts/*`.
- [ ] `AGENTS.md`: merge the project-specific sections (Project Context, Validation Workflow,
      Styling Reuse) into the generated one. `ai-tools` does not create `CLAUDE.md`; re-add it with
      `@AGENTS.md`. The generated `.claude/settings.json`, `.vscode/mcp.json` and
      `.github/skills|agents` are identical to the current ones.
- [ ] `.prettierignore`: re-add `.github/skills/` (generated content, not ours to format).
- [ ] `README.md`: project description, commands, updated `sv create` command.
- [ ] `docs/plan.md` (this file).

### 10. Replace repository contents

- [ ] On branch `migrate/sk-3`: remove all tracked files except `.git`.
- [ ] Copy `../cloudflare-site-new` over (without `.git`, `node_modules`, `.svelte-kit`, `build`).
- [ ] `npm install`, regenerate `package-lock.json`.
- [ ] Commit, open a PR to `main`, check CI and the Cloudflare preview deployment.

### 11. Optional: enhanced images (after the migration is merged)

`enhanced-img` is installed during scaffolding, but the migration ports images 1:1 as plain imports.

- [ ] Switch content images (hero, categories) to `<enhanced:img>` for AVIF/WebP and responsive sizes.
- [ ] Keep `og-image.jpg` as a plain import: meta tags need a plain URL.

### 12. Optional: Storybook (after the migration is merged)

The site also serves as a UI prototype, so Storybook may be useful for working on components from
the designs in isolation. It is kept out of the migration so that any issues there are clearly
SvelteKit 3 related.

- [ ] On a separate branch (e.g. `feat/storybook`) from the migrated `main`: `npx sv add storybook`
      (same add-on as the option in `sv create`).
- [ ] Try a few stories for existing components (e.g. `SplitHero`, cards using `.lift-card`).
- [ ] Decide whether to keep it.
