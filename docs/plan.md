# Migration plan: SvelteKit 2 → SvelteKit 3

## Approach

Instead of migrating this project in place, we scaffold a fresh SvelteKit 3 project next to it,
port the site code into it, and then replace the contents of this repository with the new project.

```
sv create  →  ../cloudflare-site-new     (fresh SK3 scaffold, incl. ai-tools)
port       →  site code moved into ../cloudflare-site-new
replace    →  ../cloudflare-site-new replaces this repo's contents on branch migrate/sk-3
```

`../cloudflare-site-new` is a local git repository (initial commit = untouched scaffold). Each step
below is committed there separately, so every change can be reviewed against the scaffold.

Git history, CI, Cloudflare secrets and Dependabot stay in this repository. The PR diff shows the
whole migration at once.

## Target versions

- `@sveltejs/kit` 3.x, `@sveltejs/adapter-static` 4.x, `sv` 1.x
- Node ≥ 22.17, TypeScript 6, Vite 8, Svelte ≥ 5.57.1, `@sveltejs/vite-plugin-svelte` 7

## SvelteKit 3 changes that affect this project

| Area           | SvelteKit 2 (current)                    | SvelteKit 3                                                       |
| -------------- | ---------------------------------------- | ----------------------------------------------------------------- |
| lib alias      | `$lib/...`                               | `#lib/...` via `package.json` `imports`; file extensions required |
| Hook types     | `Handle`, `Reroute` from `@sveltejs/kit` | from `@sveltejs/kit/hooks`                                        |
| Paraglide hook | `event.request = request`                | `resolve({ ...event, request }, ...)`                             |
| Path type      | `Pathname` from `$app/types`             | `Path`                                                            |
| tsconfig       | `extends ./.svelte-kit/tsconfig.json`    | `extends "$app/tsconfig"` + own `include` / `types`               |
| Adapter        | `adapter-static@3`                       | `adapter-static@4`                                                |

`resolve(localizeHref('/...') as Path)` keeps working: a string starting with `/` is treated as a
route ID without params and resolves to the same pathname.

Not relevant for this project: `$app/stores`, `goto` options, cookies, CSRF, remote functions,
`params`, service workers.

## Decisions

- Repository contents are replaced entirely by the new project. Only `.git` is kept as is.
- Package name: `cloudflare-site`.
- `ai-tools` is enabled during scaffolding; whatever it generates is what we use.
- Changesets are removed (`@changesets/cli`, `changeset:*` scripts). They are no longer used.
- `deploy-site/` (legacy static HTML site) is not carried over.
- All assets in `src/lib/assets/` are carried over, including currently unused images.
- The Playwright demo is kept (`playwright="demo:yes"`): its e2e test is the only smoke check that
  the site starts and a link works, in CI and against the Cloudflare preview. The vitest examples
  generated by the scaffold are kept too. We take whatever the scaffold generates and do not write
  new tests.
- The old paraglide demo route (`/demo/paraglide`) is not carried over.
- The scaffold's floating `DemoLinks` widget is removed (it would be visible on the live site).
  `/demo/playwright` stays reachable for the e2e test and is added to `prerender.entries`, since
  nothing links to it anymore and `adapter-static` only prerenders crawled pages.
